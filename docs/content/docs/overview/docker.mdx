# Docker Deployment

The multi-user edition ships as one compose stack: PostgreSQL, the Node 24 API backend, and an nginx frontend that serves the static app and proxies `/api`. The database has no host port; only the frontend is exposed (default port 3015, HTTP).

Frontend and backend images are built by GitHub Actions and pushed to GHCR (`.github/workflows/publish-images.yml`); the server pulls them instead of building locally. Log in to GHCR once with a PAT that has `read:packages`:

```bash
docker login ghcr.io -u <github-user> -p <PAT>
```

## First deployment

```bash
cp .env.example .env
# Fill in POSTGRES_PASSWORD and RATE_LIMIT_SECRET, then generate the
# credential encryption key (back it up outside the server; it cannot change later):
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

docker compose pull
docker compose up -d
curl http://127.0.0.1:3015/api/health   # {"ok":true}
```

Open `http://server-ip:3015`, register the first account, and save your upstream API key in the account settings.

Identity tables (`001/002`) are created once by the `db-init` service; workspace, credential, media, task, and history tables (`003~005`) are applied by the backend on every startup. Existing data is never cleared.

## Updating and rollback

```bash
# set IMAGE_TAG in .env to the tag produced by the workflow (sha-<short> or a version)
docker compose pull
docker compose up -d
```

Rollback: point `IMAGE_TAG` back to the previous tag, then `docker compose pull && docker compose up -d`. Database changes so far are additive only, so rolling code back does not affect data.

To build locally instead of pulling, add the build override:

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

## Backup

`scripts/backup.ps1` dumps the database, tars the media volume, and copies `.env` (which contains the encryption key), keeping the last 7 runs. Schedule it daily via Windows Task Scheduler. Restore commands are in the Chinese version of this page.

## Security note

The default deployment is LAN HTTP: credentials cross the network in cleartext, which is only acceptable on a trusted network. Add HTTPS (reverse proxy with a certificate, or a tunnel) before exposing the service to the public internet, and update `APP_ORIGIN` accordingly.
