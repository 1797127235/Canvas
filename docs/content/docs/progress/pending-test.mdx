# Pending Tests

The current release needs manual verification in these areas:

- 本地开发免登录：Vite 开发模式默认不查询身份服务、不显示登录/注册入口，画布、素材、图像/视频工作台、模板克隆、Agent、插件/快捷键及原本地渠道配置应在未启动身份后端时正常使用。`web/.env.local` 设置 `VITE_AUTH_BYPASS=false` 并重启后应恢复路由与操作入口的登录限制；生产构建和预览即使设置 `VITE_AUTH_BYPASS=true` 也不能开启豁免。该开发例外不是已登录会话，真实身份仍需服务端校验。
- 身份本地验收：注册、登录、退出、固定 7 天 HttpOnly 会话、5 次密码失败锁定 15 分钟及 PostgreSQL 固定窗口限流已实现。修复锁定到期后错误计数、正确登录并发解除锁定、迟到刷新响应覆盖登录/退出、退出失败提示、异步异常出口与会话字段契约；新增可信身份 middleware 和启动时过期清理。后端 54/54、前端 14/14 全部测试和两端类型检查通过；独立 Chrome profile 已验证表单规则、注册、重复邮箱、错误密码、登录、刷新、双标签页退出、网络错误、退出失败、锁定/到期解锁及会话过期，无未捕获页面异常。未执行构建或生产部署，等待用户最终确认。
- 身份中间阶段边界：关闭开发豁免后，游客触发模板克隆/保存素材需登录；登录后返回原模板预览且不自动操作，未接入账号存储前仍不写入旧本地数据。已登录访问私人页面显示待开放状态，不挂载旧本地列表和编辑器，Agent/旧配置仅免登录开发模式开放。浏览器已验证模板返回、无自动克隆和私人页面占位；本地数据不迁移、不删除。
- 本地代理：Vite `/api` 默认转发至 `http://127.0.0.1:4100`，可设置 `VITE_API_PROXY_TARGET`；保留来源头，服务端 `APP_ORIGIN` 必须匹配实际浏览器地址。AI 渠道请求仍是原本地浏览器直连，不是账号级服务端代发。

- Agent status removal: the canvas top bar no longer shows the external Agent connection indicator (such as "Codex not connected") next to the title; the Agent button on the right still opens the panel, and connecting a local Agent keeps chat and other features working.
- Workflow templates: the Template Library Workflow kind lists built-in workflow templates with cover, author, and tags; keyword and tag filters apply to them too. For templates with a result video, hovering a card lazily loads and plays the video muted in a loop, and leaving the card stops playback back to the cover. Clicking a card opens a modal preview titled with the template name and a "clone to edit materials, copy, and node params" hint, with Clone & edit at the top right. The preview fits all nodes, pans and zooms, renders images and plays the bundled video, and hovering nodes never reveals titles (prompts), download buttons, connection dots, or any other tools. Clone & edit closes the modal, writes the bundled media into local storage, and opens a new canvas where the prompts, params, connections, and media all work and can be regenerated, while the template itself stays unchanged.

- Template library entry: the top navigation and page title show Template Library, with Prompt and Workflow kinds. Prompts keep their existing content, Workflow is empty, and the count reads as templates.
- Local proxy removal: Settings no longer shows a Local proxy tab. Model lists and image, video, text, and audio requests go directly to the provider address.
- Preferences removal: Settings no longer shows a Preferences tab and keeps Providers, Prompt sources, and Local storage.
- WebDAV removal: Settings no longer shows a WebDAV tab, connection test, or sync action. Canvases, assets, and generation records stay in the browser, and exported settings no longer include WebDAV credentials.
- Interface language: the top bar no longer shows a Chinese/English switch, and pages, settings, Ant Design components, and dates stay in Simplified Chinese.
- Local channel file: after writing provider addresses, keys, and models into `web/public/local-channels.json` and refreshing, Settings should show those providers. An existing provider with the same address and key should only gain missing models, not be duplicated. A missing or invalid file should leave the current settings unchanged.
- 本地 H3 渠道配置：刷新后应显示 `minimax-h3`、`minimax-h3-fl2va`、`minimax-h3-ref2va` 三个视频模型；本地配置的 `removeModels` 应从已有渠道中移除 Grok 视频模型及变为空的专用视频渠道，保留 Grok 生图模型和 Seedance 模型，原默认视频模型被移除时优先选择 `minimax-h3`。H3 服务的 CORS 预检、模型查询、已有任务查询和下载响应已验证通过；画布请求仍遇到 `Unsupported mode`，服务端对 multipart 模式与素材字段的兼容仍待验证，配置完成不代表画布生成已可用。
- 顶部导航入口移除：工作台与画布页面不再显示版本号、GitHub 图标和文档图标，画布菜单也不再显示文档站入口，不再打开版本更新弹窗或跳转项目仓库、文档站；页面加载时不再请求原仓库的 VERSION 和 CHANGELOG.md。配置、主题、语言、插件和快捷键入口应保持正常。
- Analytics and upstream cleanup: the app loads no GA4/Baidu analytics scripts and sends no analytics requests; the Docker image no longer generates config.js and `ANALYTICS_*` variables have no effect; the docs site drops the business, sponsor, and Render pages, and the repo no longer carries upstream publishing GitHub Actions, Render/Vercel configs, or sponsor assets.

- Canvas image previews: canvas image nodes, the left element list, the node reference bar, my-assets cards, the asset picker, image workbench result cards and history thumbnails, and the image/video workbench reference strips all render from a preview capped at a 768px long edge, so image-heavy views no longer decode the originals. Previews live locally only: canvas data, asset data, generation history, and exported zips must never contain preview content, and previews should be cleaned up when an image is deleted or no longer used. Opening the full-size image, editing, downloading, exporting, and generation references must keep using the original; an image that is already at or under 768px, exists only as a remote URL, or uses a custom cover should fall back to the original.
- Canvas drag and connection rendering performance: Dragging a single node, a multi-selection, or a whole group should stay responsive, and the drop position after releasing should match the dragged preview. Group highlighting should appear and disappear at the right moment when dragging nodes over a group, releasing should add them to the group, and dragging them out should remove them; dragging a group node itself should not highlight any group. When zoomed or panned so only part of the canvas is visible, every connection crossing the viewport should still render (including ones whose endpoints are both off-screen), connection click selection and the context menu should still work, and the dashed preview while creating a connection should follow the cursor as before.
- Image and video size settings: Image settings should split resolution (`1k` / `2k` / `4k` / auto) from aspect ratio (`1:1`, `2:3`, `3:2`, `4:3`, `3:4`, `16:9`, `9:16`, `21:9`, `9:21`, auto) and fill W/H from that pair. Video settings should keep `480p` / `720p` / `1080p` (plus a custom `p` value) and `1:1` / `3:4` / `4:3` / `16:9` / `9:16` / `21:9` / auto, then fill W/H from that pair. Duration should be a 4–30 second slider with the current value on the right; auto ratio should disable W/H.
- Built-in video requests: without a custom call script, OpenAI-format channels should send `mode`, `first_frame`/`last_frame` or `image[]`, `generate_audio`, `watermark`, and reference videos/audio like the insertable template, and must not use `input_reference[]`. Gemini-format channels should use `predictLongRunning` with `image`/`lastFrame` or `referenceImages`, and must not report that video is unsupported. Refreshing the page should continue polling a Gemini task.
- Video generation mode: Video settings should offer First & last frame and General reference. One image is sent as the first frame, two images as first and last frames, and more than two images as general references even if first-and-last-frame mode is selected. Built-in requests and request scripts should use `frames` or `reference`.
- Gemini image generation: Gemini-format channels and the Gemini image call-script template should send `generationConfig.responseModalities: ["TEXT", "IMAGE"]` with `imageConfig.aspectRatio` / `imageConfig.imageSize`, and must not send `responseFormat`.
- Video request scripts: opening Call Script for a Video model should open a full-screen stepped editor. The left panel should follow Read the rules → Let another AI write it → Available variables, and list `videos` (File[]) and `audios` (File[]). Copy script brief should include the capability, variables, return requirements, and writing rules. Inserted templates should be async functions whose parameter lists unpack `params` (image templates must include `quality`, `size`, `count`, and `background`). The OpenAI video template should use FormData with `mode`, duration, size, resolution, audio, watermark, and reference images/videos/audios; `mode=frames` should send `first_frame` / `last_frame`, and `mode=reference` should send `image[]`, then poll and download `/content`. After pasting a script from another AI and saving, generating from the canvas with connected reference videos or audio should pass those files into the script.
- URL credential import: opening the app with a new valid `baseUrl` and `apiKey` should append a provider without changing existing providers; importing the same Base URL again, including trailing-slash or `/v1` variants, should update only that provider and remain idempotent; an API key without a Base URL or an invalid Base URL should leave all settings unchanged.
- Documentation navigation and page contents: at phone width, opening the documentation sidebar should show the current section and its description at the top. Expanding it should allow switching among Overview, Canvas Guide, Development, Progress, Business, and Support; the selected section and page list should update together while the desktop top tabs remain unchanged. At widths of 960px and above, a table of contents with hierarchical track lines should appear to the right of the article, support heading navigation, and highlight the current heading while scrolling; narrower layouts should keep the top collapsible contents control.
- Canvas Agent generation-flow references: when a generation prompt contains only `@[node:...]` references already passed through `referenceNodeIds`, the existing text, image, video, audio, or group nodes should connect directly to the generated config node without creating a duplicate prompt text node; prompts containing ordinary prose should continue creating their own prompt text node.
- Video frame capture: right-clicking a video node with content should show Capture first frame, Capture last frame, and Capture current frame. Each action should create and select a proportional image node to the right, connect the video to the image, use the player's visible position for the current frame, and leave the original playback position unchanged.

Connected nodes, the target itself, children already referenced through a group, and unsupported nodes must not be selectable again; ESC or the top hint should return to the input, and new connections should immediately update the `@` list.
- Multi-image transparency: when a multi-image node containing transparent PNG or WebP assets is expanded, transparent areas in both the primary and alternatives should reveal the canvas; switching primary images must not introduce a white or panel-colored background.

## 图片分辨率尺寸表

选择分辨率和宽高比后，W/H 按下表填写，单位为像素。预设尺寸不受「16 倍数对齐」开关影响；该开关只控制手动输入尺寸时的对齐。最终生成尺寸以所选模型的实际输出为准。

| 宽高比 | 1K | 2K | 4K |
| --- | ---: | ---: | ---: |
| **1:1** | **1024 × 1024** | **2048 × 2048** | **2880 × 2880** |
| **2:3** | 1024 × 1536 | 1360 × 2048 | 2336 × 3520 |
| **3:2** | 1536 × 1024 | 2048 × 1360 | 3520 × 2336 |
| **4:3** | 1024 × 768 | 2048 × 1536 | 3312 × 2480 |
| **3:4** | 768 × 1024 | 1536 × 2048 | 2480 × 3312 |
| **16:9** | 1536 × 864 | 2048 × 1152 | **3840 × 2160** |
| **9:16** | 864 × 1536 | 1152 × 2048 | **2160 × 3840** |
| **21:9** | 2016 × 864 | 2688 × 1152 | **3840 × 1648** |
| **9:21** | 864 × 2016 | 1152 × 2688 | **1648 × 3840** |

待验收：

- 在画布和图像工作台逐项切换 3 档分辨率与 9 种比例，W/H 应与表格一致，重新打开设置后仍选中正确档位；重点检查 1K 的 2:3、16:9、21:9 及对应竖图，以及 4K 的 1:1。
- 所有 4K 预设提交时均不应触发本地总像素或最长边限制；生成和编辑请求、调用脚本应收到所选像素尺寸。
- 分辨率为自动时保留比例选择，比例为自动时禁用 W/H；手动输入 W/H 后，对齐开关仍应按原有方式工作。
- Gemini 在质量为自动时，应将表中尺寸识别为对应的 1K / 2K / 4K；显式选择质量时维持原有优先级。视频尺寸设置应保持原有行为。
