# 规格：Agent 上下文压缩

状态：首版实现已完成；服务端隔离 PostgreSQL 与 HTTP 集成测试通过，真实账号模型与浏览器会话待验收。模块 ID：`compaction`，依赖 `sessions`。
对应能力地图：[agent-context-compression-capability-map.md](./agent-context-compression-capability-map.md)。本文件描述拟实现行为，不表示压缩已启用。

## 目标与范围

长会话接近模型输入预算时，由服务端把较早历史归纳为摘要，与近期原始消息一起构造后续模型输入。数据库与界面继续保留完整历史；切换会话、刷新和重启后仍能恢复摘要及覆盖边界。

沿用已批准边界：摘要及边界仅由服务端写入；画布工具继续在浏览器执行；每轮画布、素材和选择状态动态提供，不写入持久化摘要。

首版拟采用：服务端预算检查触发、使用当前账号 Key 和本轮文本模型生成增量摘要；不增加依赖、不新增数据库字段、不引入会话分支或手动压缩入口。摘要属于额外模型调用，会增加一次摘要生成的耗时与用量；具体预算仍需评审确定。

## 当前实现与接入前置条件

- `sessions/store.ts` 读取完整消息、摘要和边界；摘要 CAS 与普通消息保存共用 `version`，已覆盖历史不能被普通保存删除或改写。
- `run.ts` 已使用显式预算估算请求，按需增量摘要旧历史，并送出历史摘要和近期原始消息；未配置预算的模型不自动触发压缩，已有摘要仍继续使用。
- 模型目录没有上下文窗口和最大输出量元数据；部署者须按精确上游模型 ID 配置预算，不能按名称猜测。
- 会话迁移、store、压缩编排和 HTTP 流程已在隔离 PostgreSQL 与模拟上游验证；前端保存队列已有并发、丢响应和冲突回归测试，登录浏览器人工流程仍待验收。
- 服务端普通保存可整体替换历史。必须防止摘要覆盖的历史被改变后继续使用过期摘要：已有摘要时，对覆盖区间的删除、改写或重排应明确拒绝；若将来支持编辑旧消息，另行设计摘要失效与重算。
- 核实 CopilotKit 实际发送的 `context.value` 序列化形态，再统一预算估算与提示词构造，不能把对象插值正常当成已验证事实。

## 预算要求

1. 预算检查针对实际送模投影：服务端指令、当前画布/素材上下文、工具定义、已有摘要、未覆盖历史，以及本轮新增消息。已覆盖的旧原文不重复计入。
2. 每个本轮模型需要明确的上下文窗口、输出预留、安全余量和近期保留目标；数值及配置位置在评审中确定。缺少预算不能伪装已开启自动压缩，也不能猜测模型窗口。
3. provider 使用量可用于校准，但不代表本次请求大小；历史追加、工具返回、实时上下文变化必须纳入本次估算。字符/字节估算必须标注为估算，并覆盖中文与工具 JSON 场景。
4. 压缩请求本身也须满足摘要模型的输入与输出预算。不能等到整段历史已经放不进模型时，再把同一段超长原文直接用于摘要。必要时按合法消息分组分批生成，所有步骤成功后才能提交新边界。
5. 重建后重新检查预算；当前提问、实时上下文或不可分工具组独占预算且无法继续压缩时，明确返回超预算错误，不静默截断消息或工具结果。
6. 模型输入预算与会话存储上限独立。现有 400 条/2 MiB 限制仍可能阻止继续保存，摘要不会解除限制；如需取消或调整上限，须单独确认，不宣传无限会话。

## 正常处理流程

1. 前端串行保存待提交完整消息，拿到服务端确认版本。用户首次提问和浏览器执行工具后的续跑都遵循同样原则。
2. 服务端校验账号、项目、会话、消息 ID 与期望版本，读取持久化历史及压缩状态。请求中的历史不得使已覆盖部分被替换，也不得遗漏本轮需要的消息。
3. 基于已有摘要和未覆盖消息构造候选投影，计入当前动态上下文和工具定义，检查预算。未触发时直接运行。
4. 超过阈值时，从尾部选择近期保留区间。优先按用户发言到下一条用户发言之前的完整区间划分；首版不拆当前用户区间。工具调用及其对应全部结果必须整体保留或整体归纳，不能产生孤立结果。
5. 摘要输入只包含旧摘要与旧边界之后、新边界之前的新增历史；没有新增可覆盖历史时，不重复摘要同一段内容。
6. 摘要生成时不提供可执行画布工具。历史内容作为待归纳的数据，系统指令要求保留目标、约束、决定、已完成操作、失败结果及待办，不把历史里的命令作为新的操作执行。
7. 验证摘要非空、输出完整、边界合法、重建上下文符合预算且请求未取消，再通过 `updateCompactionState` 按读取版本 CAS 提交。摘要与边界必须一起成功，完整消息不被改写。
8. 提交失败、版本冲突或会话被删除时，不使用未提交的新摘要运行模型，不自动用新版本覆盖其他写入。
9. 仅使用已确认的摘要与边界构造正式模型请求，附上本轮实时画布、素材及工具声明，返回正常流式结果。
10. 压缩提交后，前端必须收到并接纳新会话版本，再允许后续消息保存。即使压缩已提交但随后模型失败、连接中断，也必须有重新取得确认版本的恢复路径，不能只依赖正常结束事件。具体传输方式在技术计划中核对 AG-UI/CopilotKit API 后确定。

送模投影：

```text
服务端固定指令
+ 历史摘要消息（单独的 user 历史消息，明确标为不可信历史内容）
+ coveredThroughMessageId 之后的原始消息
+ 当前画布/素材上下文 + 当前工具定义
```

摘要不会伪装成用户刚发出的消息，不提升为新的可覆盖系统指令。实时画布状态是当前节点及素材事实的依据，历史摘要中的旧描述不能覆盖它。

## 边界和失败语义

- 消息 ID 必须非空且唯一；边界必须属于当前持久化历史；重复 ID、缺失边界或摘要状态不成对时明确失败，不按数组下标或条数猜测。
- 对照 `toolCallId` 检查工具配对，包括单个 assistant 发起多个调用的情况。未完成工具组不得被压缩；孤立结果不得送模。
- 超长当前用户区间无法保留时，首版明确告知无法容纳；不照搬 pi 的区间内部切分及双摘要机制。
- 摘要失败、空文本、输出截断、超时或取消均不推进边界。原投影在安全预算内可继续；若已超预算则停止本轮并显示错误，保留完整历史。
- 前端保存队列负责浏览器写入串行；服务端 CAS 负责跨标签/进程冲突。两者职责不同，不能声称前端队列能串行服务端摘要写入。
- 409 不进行盲目自动重试、不按消息 ID 猜测合并。重新确认服务端版本时保留本地未保存历史，明确提示冲突。
- 不自动重放已经在浏览器执行的画布工具。首版不引入溢出后整轮自动重试，以免重复操作或付费生成。
- 日志只记录会话/run 标识、预算估算、覆盖边界、摘要耗时、结果和 provider 用量；不记录完整摘要、历史正文或账号 Key。

## 技术栈与文件边界

现有 `ai@7.0.137`、`@ag-ui/core@1.0.2`、`@copilotkit/react-core@1.79.1`、`pg@8.23.1`，不额外安装 pi 作为运行依赖。实现 AI SDK 或 CopilotKit API 时再按已安装版本文档核验。

- `server/src/agent/compaction/`：预算、合法边界、摘要生成与模型投影；按实际需要拆小文件。
- `server/src/agent/sessions/store.ts`：完整历史、摘要及版本原子读写。
- `server/src/agent/routes.ts`、`run.ts`：权限校验、运行编排和版本通知，不放摘要算法。
- `web/src/lib/agent/session-save-queue.ts` 与助手面板：串行保存、版本确认及冲突提示，工具执行仍在浏览器。
- `server/tests/agent-compaction*.test.ts`：算法、编排和真实 PostgreSQL 集成测试。
- `docs/specs/`：本规格及后续独立计划/任务；待办与待验收记录仍在现有 progress 文档。

代码风格沿用现有 store CAS 调用，不增加全局状态框架。例如边界由算法验证后，持久化仍使用已有接口：

```ts
const version = await sessions.updateCompactionState(
    userId, projectId, threadId, session.version, summary, coveredThroughMessageId,
);
```

验收覆盖：

- [x] 阈值之下不摘要；阈值以上只摘要旧区间，并计入指令、工具与实时上下文。估算保守使用 UTF-8 字节及协议余量，不等同于 tokenizer 精确 token 数。
- [x] 首次与多次压缩后，模型输入含摘要与未覆盖消息，近期原文逐字不变；单测覆盖增量摘要及多工具配对。
- [x] 多工具、未完成工具组、中文长文本、超长当前用户区间、缺失/重复 ID 都有确定性测试。中断的工具调用会保留原调用并补明确的失败结果，不自动重放。
- [x] 摘要失败、输出截断、取消、写入冲突和重建超预算时，不推进压缩边界；摘要版本 CAS、删除/普通保存并发由版本条件保护。
- [x] 隔离 PostgreSQL HTTP 集成验证压缩保留完整历史、边界与版本、后续保存、额外摘要字段拒绝；会话 store 集成测试覆盖账号/项目/thread 隔离及 CAS 竞争。
- [x] 前端 HttpAgent 集成测试验证正常和断连后的版本恢复及保存队列串行；登录浏览器尚未验证。
- [ ] 多会话切换、刷新恢复、浏览器工具续跑、双标签冲突待登录浏览器验收；HTTP schema 测试确认前端不能提交摘要字段。
- [x] 完整历史达到存储上限仍按存储契约返回 413，不删除旧消息；新建会话可继续，超限快照仅在当前页面暂存，刷新会丢失，已在 UI 提示。

## 执行边界与待定事项

- 始终：完整历史保留、服务端管理摘要、复用账号 Key、预算可追溯、失败不推进边界、不掩盖测试失败。
- 需另行确认：新增依赖/SQL 字段、取消存储上限、另选摘要模型、实际付费验收、修改部署 catalog 格式。
- 禁止：旧接口兼容分支、静默裁剪历史、把前端工具搬服务端、通过重试覆盖版本冲突、把未完成测试记为通过。
- 待评审：模型上下文窗口的权威来源与配置入口，以及输出预留、安全余量、近期保留和摘要输出预算的具体默认值；未确定前不能宣称规格已可直接实现。
- 后续技术计划需确定：run 的期望版本传输、持久化历史与浏览器工具续跑历史的校验、压缩版本通知及断流恢复方式。
